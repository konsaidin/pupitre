# Харнесс реальных данных

Node.js 22+, `unzip`, `tar`; esbuild берётся из `apps/web/node_modules`.
Данные хранятся **только вне репозитория**: `PUPITRE_DATA`, по умолчанию
`~/.cache/pupitre/datasets`. Проверяется и реальный путь через симлинки.
Внутри наборов симлинки запрещены. В репозитории находятся только реестр,
код и числовые baseline; аудио, аннотации и архивы сюда не копируются.

```sh
node tools/datasets/fetch.mjs guitarset
node tools/datasets/verify.mjs guitarset
node tools/datasets/fetch.mjs egset12
node tools/datasets/fetch.mjs alphatab-testdata
node tools/datasets/fetch.mjs guitar-techs --with guitar-techs
node apps/web/harness/run.mjs registry
node apps/web/harness/run.mjs registry --sets guitarset,egset12
node apps/web/harness/run.mjs registry --write-baseline
```

Загрузчик требует минимум 8 ГиБ свободного места на разделе хранилища.
`.part` сохраняется при обрыве сети, следующий запуск использует HTTP Range;
если сервер игнорирует Range, файл скачивается заново. Совпавший md5/sha256
исключает повторную загрузку. ZIP распаковывается через unzip, tar.gz — через
tar, в подпапку архива; пути и типы файлов проверяются до распаковки.
Содержимое не исполняется. `SOURCE.txt` содержит источник, лицензию, дату и хеши.
Маркер `<архив>.extracted` исключает повторную распаковку; если распакованные
данные повреждены, удалите этот маркер вручную и повторите fetch.
`verify` проверяет все части и хеши присутствующих архивов; отсутствие архива
при полных распакованных частях допустимо. Отсутствующий набор — `NOT FETCHED`
(exit 1), отсутствующий localOnly — `SKIPPED (localOnly)` (exit 0).

`registry.json` задаёт точные glob/expect для частей и минимальное число входов
`minN`. Поддерживаются `*`, `?`, `**` как сегмент пути. Считаются все совпавшие
обычные файлы, лишние тоже приводят к несовпадению N/N. GuitarSet дополнительно
сверяет объединение идентификаторов трёх частей и перечисляет непарные записи.
Обязательный отсутствующий набор проваливает харнесс. Отсутствующие опциональные
наборы печатаются `NOT FETCHED`, localOnly всегда пропускаются. Загруженные
опциональные наборы проверяются полностью, без строки `OK`.

EGSet12 опубликован отдельными файлами: 12 WAV, 12 JAMS, 12 GP; все они
скачиваются с индивидуальными md5. Веса TabCNN не входят в реестр входов.
alphaTab: все 1149 файлов `packages/alphatab/test-data` из v1.8.4, без изменения
содержимого. Guitar-TECHS: фиксированный поднабор всего архива P1_techniques,
по 5 файлов DI, micamp, MIDI, ego и exo; загрузка только с явным `--with`.
IDMT Guitar/Bass (CC BY-NC-ND-4.0) скачиваются **только вручную**, распаковываются
в `<PUPITRE_DATA>/<id>/`; никогда не используются в CI/сборке. Их можно проверить
локально через verify; точные числа WAV взяты из каталогов архивов Zenodo.

## Новая задача

Создайте `apps/web/harness/<имя>.ts`, экспортирующий `async function run(ctx)`.
Задача бандлится во временный ESM-файл в `os.tmpdir()` и запускается отдельным
процессом Node. `ctx` содержит `dataRoot`, `registry`, `sets`, `log`,
`skip(id, reason)` и `pool(n)`. `sets` — идентификаторы наборов из реестра,
по умолчанию все. Не выбирайте первые N файлов: обходите полный реестр.

```ts
export async function run(ctx) {
  // Здесь обрабатываются все записи выбранных частей.
  return {
    metrics: { recall: { value: 0.95, kind: 'share' } },
    registry: { 'guitarset/mono-mic': { n: 360, expected: 360 } },
    failures: [],
  };
}
```

Каждую обработанную часть возвращайте ключом `<id>/<часть>` и настоящим N/N.
`n !== expected` — провал; для обязательных наборов проверяется также `minN`.
Необработанный набор отмечайте `ctx.skip(id, 'NOT FETCHED')` или причиной
пропуска. Задача отвечает за полноту своих частей и конкретные метрики.

`await ctx.pool(4).map(items, absoluteModulePath, payload)` возвращает результаты
в порядке items. Модуль worker — исполняемый Node ESM `.mjs` с экспортом
`default async function(item, payload)` или `run(item, payload)`. Для TS заранее
соберите отдельный модуль через esbuild. Аргументы и результаты должны допускать
structured clone. Рабочие потоки переиспользуются в пределах map и завершаются
после него, в том числе при ошибке; харнесс также закрывает пулы в finally.

## Отчёты и baseline

Отчёты: `~/.cache/pupitre/reports/<задача>-<YYYYMMDD-HHMMSS>.json` (UTC).
В отчёте сохраняются выбранные наборы, пропуски, N/N, метрики, ошибки и правила
сравнения. Совпадение имени отчёта в одну секунду не перезаписывает старый файл.
Ошибки задачи дают exit 1; успешный прогон — exit 0.

Метрика имеет форму `{value: number, kind: 'share' | 'rate' | 'error'}`.
Доли лежат в 0..1: падение **больше** 0.005 проваливает прогон. Для ложных
срабатываний в минуту (`rate`) и медиан ошибок (`error`) провал — рост
**больше** 5 %. Исчезновение метрики baseline или смена kind — тоже провал.
Отсутствующий baseline печатается `NO BASELINE` и не считается ошибкой.
`--write-baseline` записывает метрики только успешного прогона без регрессии
в `baselines/<задача>.json`. У задачи registry метрик качества нет: полнота
проверяется независимо от baseline. Эталоны задач качества создавайте на полном
реестре входов; изменение состава выбранных наборов требует отдельной оценки.
