# Вокальная линия, MIDI-редактор и настройки извлечения

**Статус:** черновик, ждём ответов по открытым вопросам
**Дата создания:** 2026-07-09
**Автор задачи:** пользователь · ведёт: Claude

---

## Цель

Сделать извлечённый из песни вокал полезнее:

1. **Вокальная линия** — показывать непрерывный контур высоты голоса (f0) прямо на
   пиано-ролле, как «дорожку», по которой едет шарик. По сути это тот сигнал,
   который получился бы, если бы извлечённый вокал «спели в микрофон».
2. **Проигрывание вокала + MIDI-редактор** — слушать извлечённый вокал и править
   ноты (двигать/тянуть/добавлять/удалять/сдвигать по высоте), в которые потом
   попадать своим голосом.
3. **Настройки извлечения** — ползунки, которыми можно подкрутить качество снятия
   мелодии (в т.ч. под экстремальный вокал).
4. **Экспериментально:** петь не по MIDI-нотам, а по самой линии-контуру
   (шарик-ориентир) — то есть скоринг по непрерывной кривой, а не по плашкам.

---

## Разбор идей и как они ложатся на текущий код

### Что уже есть

- **Бэкенд** (`services/api/app/pipeline.py`): decode → Demucs (`separate_stems`) →
  pYIN f0 (`extract_notes`) → сегментация `_segment` → `map.json` со списком
  `notes[]` (каждая: `startMs`, `durMs`, `midi` — целое).
- **`vocals.wav` уже сохраняется** на диск (для отладки), `mix.wav`/`instrumental.wav`
  удаляются. Значит: превью вокала и повторное извлечение без Demucs — дёшевы.
- **Фронт** (`apps/web/src/components/PianoRoll.tsx`): рисует `notes[]` плашками,
  живой «хвост» голоса игрока (`engine.trail`) и точку текущей высоты. Скоринг
  (`engine.ts` + `scoring.ts`) сравнивает высоту с микрофона с активной нотой.

### Ключевое наблюдение

`extract_notes` считает полный кадровый контур `midi[]` (шаг ~11.6 мс), но наружу
отдаёт только нарезанные и округлённые до полутона ноты. **Непрерывная линия
теряется.** Все четыре фичи опираются на то, чтобы её сохранить.

## Предлагаемая архитектура

### Фича 1 — вокальная линия (контур f0)

- **Бэкенд:** из `extract_notes` дополнительно возвращать прореженный контур
  `pitchline` — массив `{ tMs, midi (float, NaN=тишина), conf }`. Хранить в
  **отдельном файле** `pitchline.json` (карта `map.json` остаётся маленькой, старые
  карты продолжают грузиться). Отдать эндпоинтом `GET /api/songs/{id}/pitchline`.
- **Фронт:** `PianoRoll` умеет рисовать переданный контур как непрерывную линию +
  шарик-ориентир, синхронный с `engine.songMs()`. Отдельный prop, чтобы не мешать
  игровому «хвосту» игрока.

### Фича 2 — превью вокала + MIDI-редактор

- **Превью вокала:** эндпоинт `GET /api/songs/{id}/vocal` (отдаёт `vocals.wav`
  или перекодированный mp3). В игре его НЕ играем (утечёт в микрофон) — только в
  редакторе/превью.
- **Редактор:** экран, где виден контур + ноты поверх, играет вокал, ноты можно
  двигать/тянуть/добавлять/удалять/сдвигать по высоте. Сохранение —
  `PUT /api/songs/{id}/map` (перезапись `notes[]` в `map.json`).

### Фича 3 — настройки извлечения

Кандидаты в ползунки (все реально влияют на качество):

| Параметр | Сейчас | Что делает |
|---|---|---|
| `FMIN`/`FMAX` | 65 / 1047 Гц | диапазон поиска высоты (для экстрима — расширить/сузить) |
| энергетический гейт | 5% от p95 RMS | отсечка тихих хвостов; ниже — ловит больше, но и шум |
| порог `voiced_prob` | не используется | можно включить как фильтр уверенности |
| `MIN_NOTE_MS` | 90 мс | минимальная длина ноты (короче — режем) |
| `MERGE_GAP_MS` | 80 мс | склейка соседних одинаковых нот через микропаузу |
| `SPLIT_SEMITONES` | 0.75 | насколько уход от медианы рвёт ноту |
| ширина медианы | 5 кадров | сглаживание выбросов детектора |

- **Повторное извлечение:** запускать **только этап analyze** от сохранённого
  `vocals.wav` (без Demucs — быстро). Новый эндпоинт
  `POST /api/songs/{id}/reextract` с параметрами.
- **Честно про экстрим-вокал:** гроул/скрим/фрай физически малогармоничны, pYIN там
  ненадёжен при любых ползунках — потолок качества есть. Ползунки помогут «чистому»
  вокалу в целом и частично экстриму, но не превратят шум в точную мелодию.

### Фича 4 — режим «петь по линии» (экспериментально)

- Переключатель на песне: цель — не плашки-ноты, а непрерывный контур. Скоринг —
  по близости высоты игрока к контуру в центах (усреднённо по времени), а не по
  доле удержания внутри ноты. Требует Фичу 1.

---

## План по фазам (предлагаемый)

1. **Фаза 1 — линия:** контур в пайплайне + `pitchline.json` + эндпоинт + отрисовка
   линии/шарика на ролле + превью вокала. Фундамент для всего.
2. **Фаза 2 — редактор:** экран правки нот, сохранение карты.
3. **Фаза 3 — настройки извлечения:** ползунки + reextract от `vocals.wav`.
4. **Фаза 4 — режим «петь по линии»:** скоринг по контуру, переключатель.
